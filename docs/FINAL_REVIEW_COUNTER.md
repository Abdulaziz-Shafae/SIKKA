# سكة — عداد المراجعة النهائية

الهدف: عند إكمال جميع النقاط (14/14) لا يبقى إلا **الدمج وتحويل Sikka - Testing في main acc إلى Production**. لا تغيير أو حذف من sikka acc (النسخة القديمة) قبل تحقق الهجرة والنسخ الاحتياطي.

## منهج كل نقطة
1. اقرأ كود الباك إند والفرونت وبيانات الاختبارات الموجودة قبل اتخاذ القرار.
2. سجّل **ما هو موجود / ما هو ناقص / القرار المعتمد**، واسأل المستخدم فقط إذا كانت هناك سياسة جديدة غير محسومة.
3. نفّذ التعديل على فرعي التطوير، ولا تغيّر الفروع الأساسية.
4. أضف فحصًا آليًا لما تغيّر وأعد فحوص CI. اختبر وظيفيًا على Sikka - Testing حين تتوفر صلاحية/بيانات الاختبار.
5. لا تُعلّم النقطة مكتملة إلا بوجود أدلة واضحة. إن كان الاختبار الخارجي يتطلب إعدادًا غائبًا، تبقى النقطة معلّقة.

## العداد
- [x] **01 — المجانية المؤقتة ومويَسر:** زيارات وإعادة توليد مجانية للجميع، مع إبقاء كود Moyasar معطّلًا، ولا صفحات دفع عند المجانية. إصلاح حقن الإعداد في منشئ PaymentOrderService، مع تغطية المجانية غير المحدودة واختبار سياسة الدفع القديمة بشكل مستقل. CI الباك 138/138 والفرونت ناجحان. الاختبار الحي النهائي في بيئة Testing ضمن النقطة 14. القرار السابق معتمد.
- [x] **02 — الحسابات والتسجيل والملفات الشخصية:** البريد فقط، إصلاح التسجيل (لا يُفعّل الحساب قبل الرمز)، إرسال التفعيل والاستعادة، ومراجعة جلسات الدخول. قرار حذف الحساب المعتمد نُفذ: كلمة مرور لازمة، عملية حذف فعلية للحساب والملف والبيانات الشخصية المرتبطة، وتحويل مرجع الزيارة المشتركة إلى حساب تقني محظور مع حفظ بيانات المشاركين الآخرين. مسار الحذف متاح من صفحة الملف. اختبارات H2/HTTP للحذف (الفرد، منظّم مجموعة، مشارك، كلمة مرور خاطئة، جلستان) نجحت؛ CI الباك 145/145 وCI الفرونت ناجح. **بيانات النسخ الاحتياطية والخدمات الخارجية تُراجع في النقطة 14، وحماية CSRF تُراجع في النقطة 13.**
- [x] **03 — الزيارات والأعضاء:** راجعنا SOLO / FRIENDS / FAMILY وRSVP (GOING/NOT_GOING) وجاهزية TOGETHER/SPLIT والدعوات وربط الحساب. أُصلح شرط تعديل الزيارة المكررة عند المجانية في الأعضاء والوجبات وعناصر الخطة، وأصبح الانضمام يتطلب بريدًا مفعّلًا، ومنع تدوير رمز الدعوة بعد بدء التخطيط/قفل الأعضاء. اختبارات CI المحدثة: 150/150 بدون أخطاء. اختبارات المتصفح وقاعدة Railway الفعلية في نقطة 14.
- [x] **04 — اختيار الألعاب:** مراجعة قراءة وحفظ أولوية كل لعبة بشكل مستقل في RidePreferences: MUST_RIDE / PREFERRED / OPTIONAL. يتم إرسال rideId وpriority الحقيقيين عبر backendApi.memberPreferences إلى PUT /api/v1/visit-member/preferences/{visitMemberId}، ويمنع الباك القيم غير الصحيحة والتكرار واختيار الألعاب المستبعدة ويحفظها في selectedRides. ميزة التجنب موجودة وتُحفظ في dislikedFeatures، وظهر اختبار سابق لحماية ترتيب الأولويات في TeamFlowsIntegrationTest. لا حاجة لتعديل المنطق الحالي؛ اختبار تجربة المستخدم الحقيقية ضمن نقطة 14.
- [ ] **05 — الوجبات والسناكات والمطاعم:** تفضيلات وأوقات ورحلة اختيار المطعم المبسطة.
- [ ] **06 — توليد الخطط وإعادة التوليد:** تحقق المتطلبات، منطق المجموعة والاعتماد وتأكيد الوصول؛ اترك قرار عدم تعديل استهلاك AI وعدم تغيير اعتماد تأكيد الوصول على AI قائمًا.
- [ ] **07 — الزيارة الحية:** إكمال اللعبة والراحة، أسباب التأخير، تغير الانتظار/الإغلاق، تعديل الجدول والإشعارات.
- [ ] **08 — الصلاة:** الحسابات والتوقيت والتعارض وتثبيت استراحة الصلاة في TOGETHER وSPLIT.
- [ ] **09 — الخريطة والملاحة:** خريطة نواف وإحداثياتها، مسار حقيقي وترقيم الزيارات ومصليات وخدمات؛ لا تُفعّل `امشِ لهنا` حتى تثبت دقة GPS.
- [ ] **10 — التنبيهات والإيميلات:** Brevo، n8n cron، 24h/2h، تكرار/إلغاء/تغيير الموعد، اختبار وصول فعلي.
- [ ] **11 — ملخص الزيارة والتقييمات:** العرض، صورة سكة والتصميم، إيميل الملخص ومرفقه.
- [ ] **12 — تبسيط الفرونت إند:** الأزرار والتبويبات المؤجلة، الأجهزة المختلفة، RTL/LTR وإمكانية الوصول.
- [ ] **13 — الأمان والخصوصية والتحسينات التشغيلية:** المصادقة، ملكية البيانات، الأسرار، API، المخاطر واستهلاك الذاكرة، بدون توسيع نطاق AI المستبعد.
- [ ] **14 — قاعدة البيانات واختبار النهاية للنهاية والترحيل:** مقارنة sikka acc مع main acc، نسخ احتياطية، اختبار استرجاع، بيانات الألعاب/الخريطة، تشغيل خدمات Testing، التحقق من جميع الفلوز. لا حذف للحساب القديم هنا.

## شروط الإنهاء
- CI للباك والفرونت ناجح على آخر commit في البرانشين.
- اختبارات حقيقية للتسجيل، الزيارة، العائلة/الأصحاب، الخرائط، البريد، المجانية، والملخص على بيئة Testing.
- بيانات النسخة القديمة المطلوبة نُقلت بقرار واضح وبنسخة احتياطية؛ لا نقل تلقائي للبيانات الشخصية.
- إعدادات Railway وBrevo وn8n موثقة ومتحقق منها بلا نشر إنتاجي.
- **بعد 14/14**: يبقى الدمج، ضبط نطاق Production على main acc، ثم تحقق ما بعد النشر، ثم إلغاء موارد sikka acc بإذن منفصل.
