# سكة | سجل التعديلات والأعمال المتبقية

التاريخ: ٢١ أكتوبر ٢٠٢٦

## ١. النطاق الحالي

التركيز الحالي على عمليات CRUD الأساسية، والتحقق من المدخلات والعلاقات والحالات، والتوافق مع اتفاق الفريق النهائي وملف مقارنة بيانات الملاهي. توليد AI والدفع الفعلي والإشعارات الخارجية والميزات الإضافية تُستكمل في مراحلها، ولا يُفترض أنها منفذة لمجرد وجود المودلز أو CRUD.

المراجع:
- Sikka_Final_Team_Execution_Agreement.docx
- Sikka_Facilities_Field_Comparison.xlsx
- Sikka_Facilities_SQL_JSON.docx لفحص قبول بيانات المنشآت
- تعليمات أسلوب البرمجة في AGENTS المرفق

## ٢. حالة الكود

- دُمجت أعمال الفريق وتحديث حقول بيانات الملاهي سابقًا في main بالتحديث cda3202.
- اعتمد المستخدم رفع مراجعة الخدمات الأخيرة إلى main، ومنها حصر مستوى الحماس في LOW / MILD / EXTREME. يسجل تحديث الدمج كذلك رؤوس برانشات mohammed وnawaf وshefo ضمن تاريخه.
- هذا الملف يسجل الموجود والتعديلات المحضرة؛ لا يعد إثباتًا لنجاح تشغيل المشروع كاملًا.

## ٣. ما تغير في الدمج السابق

- جمع أعمال محمد ونواف مع أعمال shefo الموجودة أصلًا في main، وإدخال تحديث حقول بيانات الملاهي وحل تعارضات RideService وPlaceService.
- إضافة حقول المناطق، أنواع خدمة الطعام والمطابخ والمحلات، وشروط المرافق والأعمار الموصى بها.
- دعم SHOP في فلترة الأماكن.
- إزالة اعتماد حالة الزيارة القديمة OPEN من خدمات التخطيط؛ OPEN تبقى حالة تشغيل صحيحة للألعاب والأماكن.
- إضافة hasCompletedRide التي تستعملها خدمة تفضيلات الألعاب، وإضافة sendNotification وgetPlanStatus.
- تحويل اعتماد الخطة إلى VisitService.changeStatus بدل تغيير READY مباشرة.
- إضافة readAt للإشعارات دون إضافة حالة READ.
- إبقاء البيانات المجهولة غير معبأة، وعدم حسم تعارض طول Adrena-Line أو اختراع إحداثيات وانتظار.

## ٥. نتيجة مراجعة الباترنز

رُوجعت جميع تعبيرات @Pattern البالغ عددها ٣٤، مع فحوص القيم المقابلة في الخدمات.

| المجال | القيم المتفق عليها |
| --- | --- |
| مستوى الحماس | LOW / MILD / EXTREME |
| الزيارة | DRAFT / PLANNING / READY / IN_PROGRESS / COMPLETED / CANCELLED |
| نوع الخطة | INDIVIDUAL / GROUP |
| نوع النشاط | RIDE / PLACE / BREAK / MEETING_POINT |
| أولوية اللعبة | MUST_RIDE / PREFERRED / OPTIONAL |
| اعتماد الخطة | PENDING / APPROVED / REJECTED؛ رد القائد APPROVED أو REJECTED فقط |
| سجل الإنجاز | COMPLETED / SKIPPED فقط؛ بلا QUEUING أو IN_QUEUE |
| الدفع | PENDING / PAID / FAILED؛ نوع المحاولة INITIAL أو RETRY |
| الإشعارات | IN_APP / EMAIL / WHATSAPP؛ الحالات PENDING / SENT / FAILED |
| الموافقات | HEALTH_STORAGE / LOCATION_SHARING / WHATSAPP / EMAIL_MARKETING |
| تفضيل اللعبة | REPEAT / AVOID / NEUTRAL |
| RSVP | INVITED / GOING / MAYBE / NOT_GOING؛ تعديل الرد لا يقبل INVITED |
| تصنيف اللعبة | THRILL / FAMILY / KIDS / WATER / ARCADE |
| حالة تشغيل المنشأة | OPEN / CLOSED / UNAVAILABLE |
| نوع المكان | RESTAURANT / SHOP / MEETING_POINT / RESTROOM / OTHER |
| خدمة الطعام | FULL_SERVICE / FAST_FOOD / BUFFETERIA / KIOSK / CART / VIP_LOUNGE |
| المطبخ | NORTH_AMERICAN / MIDDLE_EASTERN / MEXICAN / INDIAN / ITALIAN / PAN_ASIAN / MULTINATIONAL |
| نوع المحل | FLAGSHIP / LAND_STORE / RIDE_STORE / PHOTO_STORE / SPECIALTY_STORE / KIOSK / CART |
| المناطق | STEAM_TOWN / CITY_OF_THRILLS / TWILIGHT_GARDENS / DISCOVERY_SPRINGS / GRAND_EXPOSITION / VALLEY_OF_FORTUNE / CITADEL |
| دور الحساب وحالته | USER / ADMIN؛ ACTIVE / SUSPENDED / BLOCKED |

أنواع الحسابات والخطط ونقاط التجمع قيم داخلية للنظام. ملف الملاهي لا يحددها، ولذلك لا تُحذف لعدم ظهورها فيه. كذلك قائمة rideFeatures الحالية ليست مثبتة بالكامل بالملفين المرجعيين؛ تحتاج تثبيتًا عند استكمال بيانات الميزات، ولا تُنسب كلها إلى المصدر الرسمي.

## ٦. الفحوص المنفذة وحدودها

| الفحص | النتيجة |
| --- | --- |
| تعبيرات الباترنز باستخدام محرك Java | نجاح ٣٠٠ حالة قبول ورفض للتعبيرات الـ٣٤ |
| قبول بيانات ملف المنشآت | نجاح فحص ٨٣ منشأة: ٣٢ لعبة و٢٧ منفذ طعام و٢٤ محلًا؛ ٣٣٨ قيمة مقيدة بالباترنز |
| تنسيق التعديلات | نجح git diff --check |
| اختبارات الخدمات | أُضيفت ٧ اختبارات، ووُسعت اختبارات رفض مستويات الحماس القديمة؛ لم تُشغّل |
| Maven والبناء وJUnit | متعذرة؛ اعتماد Spring Boot 4.1.1 غير مخزن محليًا ولا يتاح الوصول إلى Maven Central من البيئة |
| MySQL وREST والتزامن والفلو الكامل | لم تُثبت باختبار تشغيل ضمن هذه المراجعة |

نجاح فحص التعبيرات لا يثبت نجاح الخدمات أو قاعدة البيانات. لا يمكن إعلان اكتمال CRUD بالكامل قبل تشغيل الاختبارات الأساسية ومعالجة نقاط الاستكمال التالية.

## ٧. استكمالات أساسية قبل إعلان اكتمال CRUD

هذه نقاط صحة بيانات وسلوك موجود، وليست ميزات إضافية:

1. تشغيل البناء واختبارات CRUD على Java وMySQL في بيئة تتوفر فيها الاعتماديات، والتحقق من مسارات النجاح والرفض.
2. التحقق من بنية selectedRides ومعرفات الألعاب، وJSON المستخدم في التفضيلات والمشاركين؛ صلاحية النص كـJSON وحدها لا تثبت صحة المعرفات أو القيم.
3. تثبيت قواعد الحذف للسجلات المرتبطة بزيارات وخطط ومدفوعات وإنجازات، بدل الاعتماد فقط على رفض قاعدة البيانات أو الحذف المتتابع.
4. توحيد فحص الحساب النشط في العمليات التي تخص مستخدمًا؛ التطبيق الحالي غير موحد بين جميع الخدمات.
5. معالجة حالات الطلبات المتزامنة: الانضمام والسعة وقفل المشاركين، تكرار الموافقة، والتعارض بين إلغاء الزيارة واعتماد الخطة.
6. عند تقديم اعتماد الخطة بوصفه جزءًا مكتملًا: فحص المشاركين وصحة الأنشطة والأهلية واكتمال الخطط المطلوبة؛ الفحص الحالي يراجع أجزاء فقط.

## ٨. الأعمال اللاحقة حسب مراحل المشروع

| المرحلة | المطلوب عند بدء المرحلة |
| --- | --- |
| الأمان والحسابات | تشفير كلمات المرور؛ المدخل يُسند حاليًا مباشرة إلى passwordHash. إضافة الدخول والصلاحيات والملكية لمسارات CRUD القديمة، وتفعيل البريد والاسترجاع وإعادة التحقق عند تغيير البريد. accountId في الرابط ليس إثبات هوية. |
| الموافقات | فرض HEALTH_STORAGE قبل حفظ البيانات الصحية وWHATSAPP قبل الإرسال، وتطبيق سحب الموافقة في مواضع الاستخدام. |
| أهلية اللعبة | استكمال شروط المرافق والصحة، وتمييز القيد المجهول من عدم وجود قيد، واحتساب العمر بتاريخ الزيارة. UNKNOWN لا يعني أن اللعبة آمنة. |
| توليد الخطط | تنفيذ startPlanning من زر القائد بعد الدفع المؤكد؛ توليد فردي لكل GOING ثم GROUP، ومنع التكرار، واستكمال الناقص عند الفشل. المسار الفردي الحالي لا ينفذ توليد خطط جميع المشاركين. |
| إعادة التوليد والتخطيط | تنفيذ onRideChanged والمقترحات المؤقتة واعتماد القائد، مع إبقاء الخطة الحالية حتى قبول البديل؛ إعادة GROUP عند رفض الخطة الأولى. |
| الدفع الفعلي | ربط Moyasar والتحقق من الخادم ومنع تكرار التأكيد؛ نقل الزيارة إلى PLANNING دون تشغيل AI تلقائيًا. الخدمة الحالية تنشئ محاولات PENDING فقط. |
| الإشعارات | تنفيذ عامل الإرسال ومزودي البريد وواتساب، وفحص الموافقة عند الإرسال، وإتاحة القراءة عبر readAt. الخدمة الحالية تسجل PENDING. |
| التقدم والمتابعة | حساب نسب الإنجاز دون عد اللعبة المكررة مرتين، وربط التذكيرات وn8n عند الحاجة. |
| البيانات والمسافات | استكمال شروط الألعاب المؤكدة، وحسم تعارض Adrena-Line من مصدر موثوق، ومعايرة الإحداثيات والمسارات قبل حساب مسافة المشي. لا تغيير تلقائي لقيم MEDIUM/HIGH القديمة دون مراجعة مصدرها. |
| الواجهة والنشر | بعد تثبيت العقود وتشغيل اختبارات التكامل للفلو المطلوب. |

ترتيب العمل: تثبيت CRUD وتشغيل فحوصه أولًا، ثم تنفيذ ميزات الاتفاقية مرحلةً مرحلة. وجود هذه الأعمال في القائمة لا يعني تنفيذها ضمن التعديل الحالي.
